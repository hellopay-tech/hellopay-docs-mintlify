HelloPay is a payin and payout platform for Colombia, with more of Latin America coming soon. One REST API lets your business **collect** payments, **send** funds, and **reconcile** every movement through multiple payment rails.

## Quickstart

<Steps>
  <Step title="Get a sandbox API key" icon="key">
    Create a key in the [sandbox portal](https://portal.stg.hellopay.com.co/settings/api-keys) and send it in the `X-API-Key` header. See [Authentication](/getting-started/authentication).
  </Step>
  <Step title="Configure a webhook" icon="bell">
    Register your endpoint and its authentication header so you receive final results. See [Webhooks](/getting-started/webhooks).
  </Step>
  <Step title="Create your first payin" icon="hand-holding-dollar">
    ```bash
    curl --request POST 'https://api.stg.hellopay.com.co/payins' \
      --header 'X-API-Key: YOUR_SANDBOX_API_KEY' \
      --header 'Content-Type: application/json' \
      --data '{
        "amountInCents": 100000,
        "currency": "COP",
        "rail": "NEQUI",
        "reference": "INV-2026-001",
        "inlineCustomer": {
          "name": "John Doe",
          "idType": "CO_CC",
          "idNumber": "1000000001",
          "email": "john.doe@example.com",
          "phone": "+573001234567"
        }
      }'
    ```
    The response has `status: "PENDING"`. In the sandbox, `idNumber` `1000000001` makes the payin succeed about 5 seconds later.
  </Step>
  <Step title="Confirm the result" icon="circle-check">
    Wait for the `payin.confirmed` webhook or poll `GET /payins/{id}` until `status` is final. Never treat the create response as the final result.
  </Step>
</Steps>

## How money moves

Every transaction is **asynchronous**. The create response is the initial state. The final state arrives later through a webhook or by polling.

<Visibility for="humans">
  <LifecycleFlow variant="payin" />
</Visibility>

<Visibility for="agents">
  Payin lifecycle: `PENDING` (no webhook) → `PROCESSING` (`payin.processing`) → one final status: `CONFIRMED` (`payin.confirmed`, then `payin.settled`), `DECLINED` (`payin.declined`), or `CANCELED` (`payin.canceled`). Payouts follow the same statuses but only send webhooks for final statuses. Payment links go from `PENDING` to `COMPLETED` (`paymentlink.completed`) or `EXPIRED` (`paymentlink.expired`).
</Visibility>

Read [Core concepts](/getting-started/core-concepts) for amounts, statuses, references, and polling rules shared by every endpoint.

## Go live

Before you switch from the sandbox to production, check that:

- [ ] You use a **production** API key and base URL, stored on your backend only. If your organization has an IP allowlist, your production IPs are on it.
- [ ] Your production **webhook** verifies its authentication header, replies `2xx` within 30 seconds, and deduplicates events.
- [ ] Orders are fulfilled only on a final status (`payin.confirmed` or `paymentlink.completed`), never from the create response or the `callbackUrl` redirect.
- [ ] Timed-out create requests are looked up by `reference` before any retry.
- [ ] Every flow you use passed the [sandbox test plan](/getting-started/sandbox#suggested-test-plan).

Then make one small real payin and payout to confirm the setup end to end.
