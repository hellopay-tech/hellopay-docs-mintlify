Webhooks are the recommended way to learn the final result of a transaction. HelloPay sends an HTTP `POST` with a JSON body to your endpoint each time a payin, payout, or payment link changes status.

## Set up your endpoint

<Steps>
  <Step title="Open Settings → Webhooks">
    In the [sandbox portal](https://portal.stg.hellopay.com.co/settings/webhooks) or the [production portal](https://portal.hellopay.com.co/settings/webhooks).
  </Step>
  <Step title="Enter your URL and authentication header">
    Set a header name (for example `X-Webhook-Secret`) and a long random value. HelloPay sends this header on every webhook request. It is the only verification method today: requests are not signed.
  </Step>
  <Step title="Save">
    Each organization has one webhook URL per environment, which receives every event type.
  </Step>
</Steps>

## Delivery and retries

  <SequenceFlow

      { actor: "HelloPay", title: "No 2xx within 30 s? Retry every hour", detail: "up to 5 attempts", icon: "clock-rotate-left" },
      { actor: "Your worker", title: "Process the event idempotently", icon: "gears" },
    ]}
  />
</Visibility>

- Any `2xx` response counts as delivered.
- HelloPay waits up to **30 seconds** for your response.
- If delivery fails, HelloPay retries **every hour**, for up to **5 attempts** in total.
- The same event can arrive more than once, and events can arrive out of order.
- Events that happen while no webhook is configured are not stored or sent later. Configure the webhook before you create transactions.

<Tip>
  If your endpoint was down for a long time, reconcile with `GET /payins` and `GET /payouts` instead of waiting for retries.
</Tip>

## Events

| Event | Sent when |
| --- | --- |
| `payin.processing` | The payin was sent to the rail and is waiting for the payer |
| `payin.confirmed` | The payment succeeded. Fulfill the order |
| `payin.settled` | The confirmed funds were settled in your balance |
| `payin.declined` | The payment was rejected, or expired unpaid |
| `payin.canceled` | The payment was canceled |
| `payout.confirmed` | The funds were delivered |
| `payout.declined` | The payout was rejected |
| `payout.canceled` | The payout was canceled |
| `paymentlink.completed` | The payer paid through a payment link |
| `paymentlink.expired` | The payment link expired unpaid (1 hour after creation) |

There is no webhook for `PENDING`, and payouts do not send a `processing` event.

<Note>
  **Payins created by a payment link** send `payin.processing`, `payin.confirmed`, and `payin.settled`, but **not** `payin.declined` or `payin.canceled`. Use `paymentlink.completed` and `paymentlink.expired` as the source of truth for payment links. See [Payment links](/guides/payment-links#handling-webhook-events).
</Note>

## Payloads

Every event has the same envelope:

```json
{
  "event": "payin.confirmed",
  "resource": "payin",
  "data": { }
}
```

`resource` is `payin`, `payout`, or `paymentlink`. Amounts are in pesos, and timestamps are ISO 8601 strings in UTC.

## Sample handler

```typescript Express (TypeScript)
import express from "express";

const app = express();

app.post("/webhooks/hellopay", express.json(), async (req, res) => {
  // 1. Verify the header you configured in the portal.
  if (req.header("X-Webhook-Secret") !== process.env.HELLOPAY_WEBHOOK_SECRET) {
    return res.sendStatus(401);
  }

  const { event, data } = req.body;

  // 2. Deduplicate: the same event can be delivered more than once.
  const eventKey = `${event}:${data.id ?? data.paymentLinkId}`;
  if (await alreadyProcessed(eventKey)) return res.sendStatus(200);

  // 3. Reply fast; do the real work in a background job.
  await enqueue(eventKey, event, data);
  res.sendStatus(200);
});

// In the background job:
async function handle(event: string, data: any) {
  switch (event) {
    case "payin.confirmed":
    case "paymentlink.completed":
      return markOrderPaid(data.reference);
    case "payin.declined":
    case "payin.canceled":
    case "paymentlink.expired":
      return markOrderFailed(data.reference);
    case "payout.confirmed":
      return markPayoutSent(data.reference);
    case "payout.declined":
    case "payout.canceled":
      return markPayoutFailed(data.reference);
  }
}
```

## Checklist

- Verify your authentication header on every request.
- Reply `2xx` within 30 seconds and process the event in the background.
- Deduplicate on `event` plus `data.id` (or `data.paymentLinkId`).
- Match events to orders with `data.reference`.
- Do not assume events arrive in order: a final status must never move back to `PROCESSING`.
