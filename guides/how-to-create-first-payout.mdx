A **payout** sends money from your HelloPay balance to a receiver. This guide covers Bre-B payouts, where the receiver is identified by their Bre-B key (an alias, phone number, email, or document).

## How the payout flow works

<Visibility for="humans">
  <SequenceFlow
    title="Bre-B payout"
    steps={[
      { actor: "Your server", title: "Validate the receiver's key", detail: "GET /breb/keys/{keyString}", icon: "magnifying-glass" },
      { actor: "Your server", title: "Create the payout", detail: "POST /payouts", icon: "server" },
      { actor: "HelloPay", title: "Debits your balance and sends the funds", detail: "PENDING → PROCESSING", icon: "paper-plane" },
      { actor: "HelloPay", title: "Sends the final webhook", detail: "payout.confirmed", icon: "bell" },
    ]}
  />
</Visibility>

1. Resolve the receiver with `GET /breb/keys/{keyString}` and check that the name and document match who you intend to pay.
2. Send `POST /payouts` with `rail: "BRE_B"` and the same key in `breb.keyString`.
3. HelloPay returns the payout with `status: "PENDING"` and processes it asynchronously. No webhook is sent while it is in progress.
4. HelloPay sends `payout.confirmed`, `payout.declined`, or `payout.canceled`.

<Warning>
  Your available balance must cover the amount plus fees, or the request fails with `400`. Check it with [`GET /ledger/balance`](/api-reference/ledger/get-the-current-balance).
</Warning>

## 1. Validate the Bre-B key

```bash
curl --request GET 'https://api.stg.hellopay.com.co/breb/keys/@alphamunKey01' \
  --header 'X-API-Key: YOUR_API_KEY'
```

```json
{
  "details": {
    "name": "John Doe",
    "documentType": "CC",
    "documentNumber": "1234567890",
    "bankAccountNumber": "1234567890",
    "keyString": "@alphamunKey01",
    "keyType": "ALPHANUM",
    "bankName": "BANK TEST"
  }
}
```

A `404` means the key does not exist. Do not create the payout.

<Tip>
  In the sandbox, `@alphamunKey01` is a test key that resolves. Sandbox payouts do not check the key: the outcome depends only on `inlineCustomer.idNumber`. See [Sandbox](/getting-started/sandbox).
</Tip>

## 2. Create the payout

```bash
curl --request POST 'https://api.stg.hellopay.com.co/payouts' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "amountInCents": 100000,
    "currency": "COP",
    "rail": "BRE_B",
    "reference": "OUT-2026-001",
    "inlineCustomer": {
      "name": "John Doe",
      "idType": "CO_CC",
      "idNumber": "1000000001",
      "email": "john.doe@example.com",
      "phone": "+573001234567"
    },
    "breb": {
      "keyString": "@alphamunKey01"
    }
  }'
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `amountInCents` | integer | Yes | Amount to send in cents. `100000` = 1,000 COP |
| `currency` | string | Yes | `COP` |
| `rail` | string | Yes | `BRE_B` |
| `reference` | string | Yes | Your payout ID. Echoed in responses and webhooks |
| `inlineCustomer` | object | Yes | The **receiver's** identity. In the sandbox, `idNumber` decides the outcome |
| `breb.keyString` | string | Yes | The receiver's Bre-B key, as validated in step 1 |

<Note>
  `reference` is not enforced as unique. If a request times out, search with `GET /payouts?reference=OUT-2026-001` before you retry, so you never pay twice.
</Note>

## 3. Read the response

```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "amount": 1000,
  "amountInCents": 100000,
  "currency": "COP",
  "status": "PENDING",
  "rail": "BRE_B",
  "reference": "OUT-2026-001",
  "inlineCustomer": {
    "name": "John Doe",
    "idType": "CO_CC",
    "idNumber": "1000000001",
    "email": "john.doe@example.com",
    "phone": "+573001234567"
  },
  "errorCode": null,
  "createdAt": "2026-01-01T00:00:00.000Z",
  "updatedAt": "2026-01-01T00:00:00.000Z",
  "resultAt": null,
  "organizationId": "123e4567-e89b-12d3-a456-426614174000",
  "targetData": {
    "keyString": "@alphamunKey01"
  }
}
```

- `status: "PENDING"` means the payout was accepted. It is not the final result.
- `targetData` holds the destination. HelloPay adds `bank` once processing starts.
- Confirm the result with the `payout.confirmed`, `payout.declined`, or `payout.canceled` [webhook](/getting-started/webhooks), or poll `GET /payouts/{id}`.

## Other payout rails

The API also accepts `TRANSFIYA` and `NEQUI` payouts. Contact [support](mailto:support@hellopay.com.co) to enable them for your organization. Request fields are listed in the [API reference](/api-reference/payouts/create-a-new-payout).
