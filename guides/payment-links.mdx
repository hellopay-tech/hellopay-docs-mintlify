Use `POST /payment-links` to get a checkout page hosted by HelloPay. You redirect the payer to the returned `paymentLinkUrl`, and they pay with any method enabled for your account. You do not have to build a checkout UI or handle rail-specific data.

## How it works

1. Send `POST /payment-links` with the amount, your `reference`, a `callbackUrl`, and optional defaults.
2. HelloPay returns `paymentLinkUrl`. Redirect the payer to it right away.
3. The payer chooses a payment method and completes the payment on the hosted page.
4. HelloPay sends `paymentlink.completed` when the payer pays, or `paymentlink.expired` if 1 hour passes without a payment.
5. When the flow ends, successful or not, the payer's browser returns to your `callbackUrl`.

## Create a payment link

```bash
curl --request POST 'https://api.stg.hellopay.com.co/payment-links' \
  --header 'X-API-Key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "amountType": "FIXED",
    "amountInCents": 100000,
    "reference": "INV-2026-001",
    "callbackUrl": "https://your-app.com/checkout/return"
  }'
```

### Request fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `amountType` | string | Yes | `FIXED`: the payer is charged exactly `amountInCents`. It is the only supported value |
| `amountInCents` | integer | Yes | Amount in cents, minimum `100`. `100000` = 1,000 COP |
| `reference` | string | Yes | Your order ID. Returned in payment-link webhooks |
| `callbackUrl` | string | Yes | Where the payer returns when the flow ends |
| `rail` | string | No | `PSE` or `BRE_B`. Restricts the link to that method. Omit it to offer every enabled method |
| `inlineCustomer` | object | No | Payer data to pre-fill. If omitted, the payer enters it on the hosted page |
| `pse` | object | No | Only when `rail` is `PSE` |
| `pse.bank` | string | When `pse` is sent | Preselects the payer's bank. Use a [PSE bank code](/guides/payin-pse#supported-banks) |

### Response

```json
{
  "paymentLinkId": "4a8f2e1b-7c3d-4e5a-9b6c-8d1f2e3a4b5c",
  "paymentLinkUrl": "https://pay.hellopay.com.co/link/V1JKU0tQNU02Wklp5lf2gAY8DYXizUKPzcG39x4i_A",
  "status": "PENDING",
  "createdAt": "2026-04-20T10:00:00.000Z",
  "expiresAt": "2026-04-20T11:00:00.000Z",
  "rail": null,
  "inlineCustomer": null
}
```

<Warning>
  Payment links expire **1 hour** after creation (`expiresAt`). Do not reuse an expired link: create a new one.
</Warning>

## Choose the checkout experience

Every optional field narrows what the payer sees on the hosted page:

| Experience | Send | Result |
| --- | --- | --- |
| Open checkout | No optional fields | The payer chooses the method and enters their details |
| Restricted method | `rail` | Only that method is shown (`PSE` or `BRE_B`) |
| PSE with the bank selected | `rail: "PSE"` and `pse.bank` | The payer skips the bank selection |
| Pre-filled payer | `inlineCustomer` | The payer skips the details form |
| Restricted and pre-filled | `rail` and `inlineCustomer` | Fastest checkout when you know both |

<Note>
  **Nequi** appears on open links when it is enabled for your account, but it cannot be set as `rail`. To offer Nequi, omit `rail`. A Bre-B link always shows a QR code.
</Note>

## Handling webhook events

Payment links have their own events. You need a webhook configured to receive them. See [Webhooks](/getting-started/webhooks).

| Event | `data.status` | Meaning | What to do |
| --- | --- | --- | --- |
| `paymentlink.completed` | `COMPLETED` | The payer paid | Fulfill the order |
| `paymentlink.expired` | `EXPIRED` | 1 hour passed without a payment | Cancel the order or send a new link |

<Warning>
  Use `paymentlink.*` events as the **source of truth** for payment links. The payin created by the link also sends `payin.processing`, `payin.confirmed`, and `payin.settled`, with `data.paymentLinkId` set, but it **never** sends `payin.declined` or `payin.canceled`. If your handler already processes `payin.confirmed`, skip events that have a `paymentLinkId` so you do not fulfill the order twice.
</Warning>

`data.amount` is in pesos. Match the event to your order with **`data.reference`**.

<Note>
  Do not match `paymentlink.completed` by `data.paymentLinkId`: in that event it currently carries a short link code instead of the `paymentLinkId` returned when you created the link. `paymentlink.expired` uses the creation ID. Also handle a `paymentlink.completed` that arrives **after** `paymentlink.expired`: a payer who started paying just before expiry can still complete, and the money was collected.
</Note>



```typescript
app.post("/webhooks/hellopay", express.json(), async (req, res) => {
  // Verify your webhook auth header first. See /getting-started/webhooks.
  const { event, data } = req.body;

  if (event === "paymentlink.completed") await markOrderPaid(data.reference);
  if (event === "paymentlink.expired") await markOrderExpired(data.reference);

  // payin.* events with a paymentLinkId belong to a link payment, which the
  // paymentlink.* events above already cover. Acknowledge and ignore them.

  res.sendStatus(200);
});
```

## Callback redirect

When the flow ends, successful or not, HelloPay redirects the payer to your `callbackUrl`. Use it to show a status page. The redirect happens in the payer's browser and can be skipped or repeated, so it is never proof of payment.

## Check a link's status

Call `GET /payment-links/{paymentLinkId}` to read a link's current `status` (`PENDING`, `COMPLETED`, or `EXPIRED`), for example before you decide to send a new one.
