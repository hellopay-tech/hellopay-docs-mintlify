Use `rail: "BRE_B"` to collect through Bre-B, Colombia's instant payment system. HelloPay generates a one-time Bre-B key (and optionally a QR code) for the payment. The payer sends the money to that key from any Bre-B-enabled bank or wallet.

Before you start, read the [Payins overview](/guides/how-to-create-first-payin) and [configure webhooks](/getting-started/webhooks).

## How the Bre-B flow works

<Visibility for="humans">
  <SequenceFlow
    title="Bre-B payin"
    steps={[
      { actor: "Your server", title: "Create the payin with breb.keyType", detail: "POST /payins", icon: "server" },
      { actor: "HelloPay", title: "Returns PENDING with keyString: null", icon: "hourglass-half" },
      { actor: "Your server", title: "Polls until keyString (and qrString) are set", detail: "GET /payins/{id}", icon: "arrows-rotate" },
      { actor: "Payer", title: "Pays the key or scans the QR in their bank app", icon: "qrcode" },
      { actor: "HelloPay", title: "Sends the final webhook", detail: "payin.confirmed", icon: "bell" },
    ]}
  />
</Visibility>

1. Create the payin with `rail: "BRE_B"` and `breb.keyType`.
2. HelloPay returns the payin with `status: "PENDING"`. `sourceData.keyString` is `null`, and `sourceData.checkoutUrl` is already set.
3. Poll `GET /payins/{id}` until `sourceData.keyString` is set (and `sourceData.qrString` for `QR_CODE`). The payin is now `PROCESSING`.
4. Show the key or QR to the payer, or redirect them to `sourceData.checkoutUrl`, a HelloPay page that shows it for you.
5. HelloPay sends `payin.confirmed`, `payin.declined`, or `payin.canceled`.

<Warning>
  After 20 minutes, HelloPay checks the payin with the Bre-B network. If the payer never paid, it becomes `DECLINED` (for example `errorCode: BRE_B_PAYIN_EXPIRED`). After the payin reaches a final status, `qrString` is cleared.
</Warning>

## Choose a key type

| `breb.keyType` | Returns | Use it when |
| --- | --- | --- |
| `SINGLE_USE` | `sourceData.keyString` | The payer types the key into their bank app |
| `QR_CODE` | `sourceData.keyString` and `sourceData.qrString` | You can show a QR the payer scans |

## Request

      --header 'Content-Type: application/json' \

        "amountInCents": 100000,

### Bre-B fields

| Field | Required | Description |
| --- | --- | --- |
| `breb.keyType` | Yes | `SINGLE_USE` or `QR_CODE` |
| `callbackUrl` | No | Where the payer returns from `sourceData.checkoutUrl` |

The shared fields are described in the [Payins overview](/guides/how-to-create-first-payin#request-fields).

<Note>
  For payins, `breb` takes `keyType`. For [payouts](/guides/how-to-create-first-payout), `breb` takes the receiver's `keyString`. Do not mix them.
</Note>

Responses are shortened here. See the [Payins overview](/guides/how-to-create-first-payin#sample-response) for every field.

| Field | Description |
| --- | --- |
| `sourceData.keyType` | The key type you requested |
| `sourceData.keyString` | The key the payer sends money to. `null` until ready |
| `sourceData.qrString` | `QR_CODE` only. A `data:image/png;base64,...` image you can use directly as an `<img src>` |
| `sourceData.checkoutUrl` | HelloPay page that shows the key or QR to the payer |

## Render the QR

`qrString` is already an image, so you do not need a QR library:

```html
<img src="data:image/png;base64,iVBORw0KGgo..." alt="Scan with your bank app to pay" width="240" height="240" />
```
